# Vidu 原生音画适配验证记录

本记录对应 2026-10-27 的可选实验接入。本页不沿用旧版“静音源时间线”或波形对齐方案的通过结果，也不把自动化通过视为真实商业服务验收。

## 本次自动化：已通过（2026-10-27）

- [x] 135 项示例单元与本地 WebSocket 测试。
- [x] Vidu 未声明 `playback.receipts`，不发送任何播放成功、完成或取消回执。
- [x] 原生媒体播放，不创建静音源播放器或重排音视频。
- [x] 打断立即静音、暂停、解绑旧流；旧 epoch 的凭据、回调和媒体不能复活。
- [x] 远端 interrupt + hangup；下一条有效回复创建新 live/channel，旧音频不上传到新会话。
- [x] 连接、播放失败及会话到期明确报错、停麦，重连后可恢复，不自动重播。
- [x] DHAV 原有真实播放回执、打断、降级及重连回归。
- [x] 桌面拖动卸载清理、客户端构建、修改源码 ESLint 和 diff 检查。
- [x] RTC 输入就绪无需等待返回媒体，避免首包循环等待。
- [x] Gateway 真实本地 socket 集成覆盖 legacy、有回执和显式无回执三条路径。

Gateway 服务端测试全集和相关专项测试通过：覆盖无回执字幕、会话记录、乱序转录、有界清理、打断、待续接工具调用、通知保留，以及标准回执与传统客户端兼容性。最终 GitHub CI 状态以 PR 检查为准。

本地测试环境为 Node.js 22.22.0、npm 10.9.4；项目声明要求 Node.js ≥ 22.22.2。
两组 Chromium 浏览器 smoke 均通过。当前提交的 GitHub CI 结果以 PR 检查为准。

在示例目录运行：

```sh
npm test
npm run build:client
npx playwright install chromium
npm run test:browser
npm run test:browser:vidu
```

两组浏览器 smoke 均加入 CI。测试使用假的 Gateway/供应商 SDK 和本地媒体，不能验证真实供应商的播放边界、音画同步或计费行为。

## 真实服务：待部署者验证

本次未进行付费 Vidu/ARTC 端到端验收。需记录短句、长句、多轮、播放中打断、打断后首帧延迟、弱网、媒体失效和会话释放，确认实际音画同步及费用。完整清单见 [部署验证](implementation-plan.zh.md)。

客户端现已将输入就绪与媒体就绪分开：入会并配置接收后，`onInputReady` 放行首包 PCM，不要求供应商提前发布音视频轨。发出音频后才等待媒体就绪，并用有界超时处理无输出；`onReady` 不产生播放完成回执。真实服务仍需验证首包内容完整、音画同步及重连后的延迟，不能只凭 Mock 推定体验一致。

**已知能力限制：**当前预览没有逐回复播放完成证明。配套 Gateway 按生成状态推进普通对话，不伪造实际播放；自动后台结果通知保持 pending，可主动查询任务状态。这是可选接入示例的能力范围，不适合依赖自动播报确认的生产流程。旧视频与历史测试不改变本版真实服务尚未验收的结论。
