# 示例贡献规范

[English](README.md) | 中文

示例用于展示基于 qwen-audio-agent 的集成和应用场景。本规范明确示例 README 的
内容要求与审核依据，适用于新增示例；已有示例在较大幅度更新文档或集成实现时逐步
对齐，不表示现有示例均已符合规范。

## 文件与语言

- 每个示例放在 `examples/<小写连字符名称>/` 下。
- 提供英文 `README.md` 和中文 `README_ZH.md`，标题下方放置双向语言链接。
- 按以下顺序使用八个章节及对应标题。项目简介直接放在语言链接下方，无需另设标题。
- 两种语言的能力、前提条件、命令、默认值、限制和署名保持一致；翻译说明文字，
  不翻译标识符和命令。
- 表达简洁、客观，详细内容通过链接引用，避免重复。演示、截图和评测结果可放在
  相关章节的子节中，但不能替代必需内容。
- 不适用的要求简要注明，不为凑齐章节虚构能力。配置示例使用占位符，不使用真实密钥。

## README 必需结构

### 1. 项目简介 / Project overview

在标题和语言链接下说明示例做什么、面向什么场景、展示框架的哪种扩展能力。
明确它是本地应用、外部服务集成，还是配置示例；涉及上游项目时提供链接。
不要把可选示例的能力描述成默认应用已内置的能力。

### 2. 核心能力 / Core capabilities

列出已经实现、用户可感知的能力，区分真实功能、模拟实现和未来计划。
避免宣传性描述，也不要重复简介。

### 3. 架构边界 / Architecture and boundaries

说明框架、示例代码、外部服务各自的职责与数据流。指出采用的公开接口或协议，
链接到接入入口；如有额外进程，说明由谁启动和关闭。

示例专属逻辑和依赖应留在示例内，复用公开扩展点，不直接导入运行时私有实现，
不重复实现框架能力。确需修改核心时，PR 必须说明其通用性并补充独立测试，
不能让默认运行时隐式依赖该示例。必要时使用简短表格或图说明边界。

### 4. 快速开始 / Quick start

提供可复现的最短路径：前提条件 → 安装依赖 → 配置 → 启动 → 访问 → 一次成功交互
→ 退出。说明命令执行目录、所需服务或凭据、支持平台和预期结果。需要多个终端或
平台专属命令时明确标注，不隐含要求用户已构建、已启动服务或已购买账号。

### 5. 配置与数据 / Configuration and data

说明必填项、可选项、默认值，以及适用时的配置优先级，与代码和 `.env.example`
等配置模板保持一致。通用框架配置通过链接引用，不复制整份配置参考。

说明哪些数据会发送到外部、本地数据存在哪里、是否复用或修改用户原有配置，
以及重启后保留什么。说明清理方法和凭据处理方式，涉及远端时注明保留策略的限制。
不要暗示删除本地文件就等于删除远端数据。

### 6. 验证与限制 / Validation and limitations

提供可执行的验证命令与预期结果，或手工验收步骤。区分自动化模拟测试、真实服务
测试和未验证行为，列出已知的平台、依赖、性能与功能限制。涉及评测数据时，注明
测试版本、条件和方法。

行为变更应有与风险相称的回归覆盖，包括相关失败路径；只能手工验证的部分在 PR
说明。CI 通过不代表真实服务行为已验证，不得声称执行过未运行的测试。

### 7. 替换扩展 / Replacement and extension

基于实际配置、接口或入口文件，说明如何替换外部服务或定制场景，哪些部分通用、
哪些依赖具体实现，以及如何恢复默认配置。需要修改代码时明确说明，不承诺未经
验证的即插即用兼容性，也不为填充此章节额外设计抽象层。

### 8. 作者与致谢 / Authors and acknowledgements

列出示例作者或贡献者的实际贡献，附公开主页或 PR 链接。将作者署名与上游项目、
依赖库和素材致谢分开，提供来源链接。改编内容保留原始署名，并遵守适用的许可与
署名要求。不虚构作者，也不暗示获得上游官方背书。

## 审核清单

- [ ] 中英文 README 按顺序包含八项内容，行为描述一致。
- [ ] 能力、边界与实现一致；核心改动有充分理由。
- [ ] 快速开始明确执行目录和全部前提条件。
- [ ] 配置、数据流、持久化和清理方式准确。
- [ ] 验证可复现，明确区分模拟测试、真实测试及限制。
- [ ] 替换扩展说明指向实际接口或文件。
- [ ] 包含作者、上游来源及适用的署名信息。
- [ ] 链接有效，未提交凭据、私人数据或运行时生成文件。

PR 中记录实际验证结果及偏离规范的说明。本清单辅助审核，不替代代码评审和适用的
CI 检查。通用要求见仓库[贡献指南](../CONTRIBUTING.md)。
