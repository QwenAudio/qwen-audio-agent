# 万能工具独立实验

此分支从上游 `76aec3e3` 创建，不包含此前 ASR review、能力查询或 JEV 实验的修改。
切换至 `experiment/universal-tool` 并使用原有启动命令即可；本实验不新增配置开关。

前台默认展示的通用委托入口改为 **万能工具**（调用名 `universal_tool`），说明为：

> 万能工具，可以用于一切情况，由后台 Agent 利用其工具与执行环境处理请求。
> 效率较低，在其它工具适用时优先使用其它工具。新增工作不会替换或取消已有工作。

参数与 `spawn_thinking` 共享同一 schema：`objective` 必填，`input_refs` 可选。
两个入口调用同一 `executeSpawnThinkingToolCall`，沿用任务提交、同轮去重、附件携带、
受理回执、结果通知和既有失败处理，没有新增能力探测或模型审核流程。
“可以用于一切情况”是工具的适用范围说明，不保证请求一定成功；“效率较低”是路由提示，
不增加等待或人为延迟。

默认模型工具列表隐藏 `spawn_thinking`，避免两个通用入口竞争；原调用仍可兼容处理，
与万能工具共享任务去重。原 `spawnThinkingDescription` 不改变万能工具的说明。
后台未配置时，两入口均不可调用；临时断连仍沿用原失败处理。
已有工作继续使用 `update_agent_task`，状态查询与取消工具保持原有机制。

主 prompt 的 Routing 规则优先使用适用的专用工具，其余请求交给万能工具，并规定：

> 仅当万能工具 `universal_tool` 明确表示做不到时，才向用户说明缺少对应能力。

已删除“不要未经尝试就声称做不到”“即使不确定后台是否支持”以及
“当前工具列表不代表后台的完整能力”等原说明。
能力结论来自实际工作结果，受理回执本身不代表完成或能力限制。

座舱评测的委托识别同时接受新旧工具名，避免将万能工具委托误算为前台直接执行。
本分支未改变模型、后台 prompt、评分方式或评测超时。
