# PR 说明草稿：Vidu 原生音画适配与打断隔离

接入 Vidu S2 Avatar / ARTC，保留双连接数字人客户端、桌面浮窗、角色图片及演示视频。数字人运行时代码只在 example 内，使用现有公开 Client SDK 和 GCP。

同一示例提供默认的自部署 DHAV/Mock 和可选的商业 Vidu 接入。主框架只补充显式协商无播放回执时的通用降级，不添加供应商逻辑、公开协议字段或厂商 SDK 依赖。

## 本次修正

- 保留供应商原生声音与音画同步，不拆轨重排、不依赖波形匹配或完成时间估算。
- 删除静音源播放器与原声对照开关。Vidu 不协商 `playback.receipts`，不发送无法证实的播放回执；DHAV 的回执不变。
- 用户打断时本地立即静音、暂停并解绑旧媒体；服务端尽力发送 type 7 interrupt 后 hangup。
- 下一条有效回复创建新 epoch/live/RTC channel，隔离旧凭据、回调及迟到媒体。重新建连增加延迟，也可能增加会话费用。
- 数字人失败明确报错、停麦并要求重连，不自动重播已经可能听过的音频。
- CI 同时运行 DHAV 和 Vidu 浏览器 smoke；桌面拖动监听在卸载时清理。
- RTC 输入就绪与媒体就绪分离，`onInputReady` 不等待远端轨，避免服务依赖首包才发布媒体时的循环等待。
- Gateway 展示无回执客户端的生成字幕、记录普通对话并在生成完成时释放调度；不伪造播放完成。自动后台结果通知保持 pending，框架任务记录及查询/控制接口保留，legacy 行为不变。本例不包含完整任务管理 UI。

## 已知能力限制

公开接口没有可关联回复的媒体结束事件，也没有可用于确认旧输出已排空的 interrupt ack，来源见 [Vidu 指南](vidu.zh.md#回执边界)。源 `audio.done`、RTC 入会或另一条静音音轨都不能代替真实播放完成。

Vidu 通过 `VIDU_EXPERIMENTAL=1` 显式启用，默认关闭。该接入不适合依赖自动播报确认的生产流程，也不提供模型历史的精确听到位置截断。本版真实 Vidu 服务尚未验收；这些限制须与可选示例一同披露。

Vidu 需要包含通用无回执降级的 Gateway；对应版本发布前应使用本分支源码，旧已发布版本可能卡在字幕/调度等待，不应描述为仅复制示例即可兼容所有版本。

本次测试结果和待验收项目见 [验证记录](presentation-validation.zh.md)。旧视频、历史对齐实验以及旧版测试结果不作为当前实现已通过的证明。
