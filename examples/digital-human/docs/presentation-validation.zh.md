# Vidu 原生音画适配验证记录

本记录对应 2026-10-27 的改造方向。当前 PR 保持 Draft；本页不沿用旧版“静音源时间线”或波形对齐方案的通过结果。

## 本次自动化：已通过（2026-10-27）

- [x] 132 项示例单元与本地 WebSocket 测试。
- [x] Vidu 未声明 `playback.receipts`，不发送任何播放成功、完成或取消回执。
- [x] 原生媒体播放，不创建静音源播放器或重排音视频。
- [x] 打断立即静音、暂停、解绑旧流；旧 epoch 的凭据、回调和媒体不能复活。
- [x] 远端 interrupt + hangup；下一条有效回复创建新 live/channel，旧音频不上传到新会话。
- [x] 连接、播放失败及会话到期明确报错、停麦，重连后可恢复，不自动重播。
- [x] DHAV 原有真实播放回执、打断、降级及重连回归。
- [x] 桌面拖动卸载清理、客户端构建、修改源码 ESLint 和 diff 检查。

本地测试环境为 Node.js 22.22.0、npm 10.9.4；项目声明要求 Node.js ≥ 22.22.2。
两组 Chromium 浏览器 smoke 均通过。当前提交的 GitHub CI 结果以 PR 检查为准。

在示例目录运行：

```sh
npm test
npm run build:client
npx playwright install chromium
npm run test:browser
npm run test:browser:vidu
```

两组浏览器 smoke 均加入 CI。测试使用假的 Gateway/供应商 SDK 和本地媒体，不能验证真实供应商的播放边界、音画同步或计费行为。

## 真实服务：待部署者验证

本次未进行付费 Vidu/ARTC 端到端验收。需记录短句、长句、多轮、播放中打断、打断后首帧延迟、弱网、媒体失效和会话释放，确认实际音画同步及费用。完整清单见 [部署验证](implementation-plan.zh.md)。

还需确认供应商在首包 PCM 上传前就发布音频与视频轨。当前客户端等待入会、两条轨订阅及原生播放成功后才发送排队音频，以免丢失开头；入会后 15 秒仍未就绪会报错停播，不会无限等待。若服务必须收到 PCM 才发布轨，需要依据供应商明确的就绪协议调整，不能只凭 Mock 通过推定时序兼容。

**合并阻塞仍存在：**供应商需要提供可关联回复的媒体结束信号，并与播放器实际排空形成完成证明。当前不协商回执的预览无法确认任务播报已送达；即使本地测试全部通过，也不能把该限制写成已解决。
