# 数字人客户端部署验证

本页是双连接改造的验收清单，取代旧的 Gateway 内嵌数字人实施计划。

## 自动化

在 examples/digital-human 下执行：

```bash
npm ci
npm test
npm run build:client
npx playwright install chromium
npm run test:browser
npm run test:browser:vidu
```

不需要模型密钥、不启动真实 Gateway、不调用 GPU / 付费 API。测试使用现有 Gateway 消息形状，验证音频输入结束、全量清理、渲染取消与真实播放回执；不依赖框架补丁或精确模型终态。

## 请原作者验证自部署 DHAV

使用已安装框架的常规配置启动普通 Gateway，再独立启动本示例，连接已经部署的 FlashHead / OpenAvatarChat 服务。无需示例专用 Gateway 分支、digitalHuman 注入或定制 WebRTC worker。单独复制示例时安装官方 SDK 包即可构建。

- [ ] 创建会话成功，长期令牌不出现在浏览器配置 / 日志。
- [ ] 连续至少五轮对话，后续轮次不瞬间播放、不卡住、不沿用旧时钟。
- [ ] 文本和语音输入都正常；麦克风静音不影响数字人继续播放。
- [ ] 说话中打断，旧画面 / 音频不复活，新回复正常。
- [ ] `audio.done` 到达而渲染仍继续时，播放不会被提前截断。
- [ ] 全量 `playback.clear` 清除当前与排队媒体；通用 `error` 不被猜测为某条回复的模型终态。
- [ ] 首次媒体前服务失败，可回退普通音频一次。
- [ ] 已播放部分内容后服务失败，不从头重复整句。
- [ ] 新会话、断线重连、关闭页面后，远端会话正确释放。
- [ ] 观察真实音画同步、首帧延迟、长句缓冲及资源占用。

## Vidu 原生音画预览验证

- [ ] 未声明 `playback.receipts`，没有静音源播放器或任何 `playback.*` 回执。
- [ ] 同一原生媒体元素播放供应商音视频，没有另一条源音频同时出声或重排媒体。
- [ ] 语音、按钮与新文字触发打断后，本地立即静音、暂停、解绑旧流。
- [ ] 旧 live 收到 interrupt 与 hangup；不将请求发送成功当成远端排空确认。
- [ ] 下一条有效回复建立新 epoch/live/channel，迟到媒体、凭据和回调不复活旧输出。
- [ ] 正常 `audio.done` 只结束输入，不估算完成或截断仍在播放的长句。
- [ ] 失败及到期明确报错、停止收音，重连恢复；不自动从头重播音频。
- [ ] 长期 Key 留服务端，结束/重连释放会话，待机和重连费用及 30 分钟上限明确。
- [ ] 真实服务下检查长句、多轮、口型、音画同步、打断后首帧延迟及弱网表现。
- [ ] 供应商提供逐回复输出结束边界，能够结合播放器排空证明真实完成后，再验收任务播报和交付确认。
