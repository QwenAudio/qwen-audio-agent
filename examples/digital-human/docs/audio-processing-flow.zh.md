# 数字人音频与控制流程

[返回总览](../README_ZH.md) · [适配器契约](provider-contract.zh.md)

两种适配器共用标准 Gateway 输入和助手音频事件，但播放确认能力不同。回执是客户端到 Gateway 的状态；`playback.clear` 则是 Gateway 到客户端的停止指令。

## 媒体路径

| 路径 | 声音与画面 | 播放确认 |
| --- | --- | --- |
| DHAV | Gateway PCM → DHAV 服务 → 配对 PCM/I420 → 本地 WebAudio/canvas | 实际起播、输出结束且本地排空、取消产生回执 |
| Vidu | Gateway PCM → 示例 Vidu 服务端适配器 → Vidu/ARTC → 同一原生媒体元素 | 不协商或发送播放回执，供应商逐回复完成边界尚缺失 |

Vidu 不另建静音 PCM 播放器，不用输入时长或静音间隙估算远端完成。原生音视频由浏览器和 RTC 处理同步，不额外拆轨重排。

## Vidu 输入和正常播放

1. 用户麦克风或文字经公开 Client SDK 发给普通 Gateway；模型及工具仍按原配置运行。
2. `audio.delta(responseId)` 的 PCM 经有界队列转交 Vidu，原字节上传，不插入额外静音。
3. Vidu 返回的原生音视频进入当前 RTC 媒体元素。
4. `audio.done(responseId)` 仅封口输入，不挂断、不估算排空、不发送 `playback.ended`。
5. 会话结束或到期时释放自有 live 和 RTC 资源；待机期间可能计费。

首包发送等待的是入会和接收配置完成后的 `onInputReady`，不是远端音视频轨。媒体返回后 `onReady` 更新展示状态，不向 Gateway 声称播放完成。

配套 Gateway 对显式未协商播放回执的客户端，按生成状态展示字幕、保存普通对话并释放生成侧调度；自动后台结果通知保持 pending，不领取播报。传统客户端路径不变，也不产生虚构的播放回执。

## Vidu 打断和下一轮

1. 语音打断使用 Realtime/Gateway 的现有事件；按钮打断和新文字输入先触发本地停止。
2. 本地立即静音、暂停并解绑旧媒体，旧 epoch 回调及后续旧回复 PCM 失效。
3. 服务端尽力向旧 live 发送 type 7 interrupt，再发送 hangup 并关闭连接。没有远端 ack 时，不声称已验证旧服务排空。
4. 下一条有效回复创建新 epoch/live/channel。旧流不会通过重新解除静音进入新回复。
5. 初始化、播放或连接失败则报错停麦，要求重连，不自动重播原音频。

正常完成与用户打断不能混为一谈：没有收到下一轮输入，不代表上一轮已经播完；主动停止旧会话也不等于自然播放成功。新会话隔离会增加重连延迟与可能的会话费用。

## 回执能力与使用限制

| 事件或能力 | DHAV | Vidu 当前预览 |
| --- | --- | --- |
| `playback.receipts` | 协商支持 | 不声明 |
| `playback.started/ended/cancelled` | 由真实媒体生命周期产生 | 均不发送 |
| `playback.clear` | 清理当前和排队媒体 | 立即停止并隔离旧 RTC |
| 麦克风静音 | 只影响采集 | 只影响采集 |
| 故障后的音频回退 | 首次起播前可回退一次 | 不自动重播，报错停麦并要求重连 |

Vidu 当前无法向 Gateway 证明任务结果是否实际播放、是否完成，不适合依赖自动播报确认的生产流程。框架任务记录和查询/控制接口保留，可主动询问任务状态；本例没有完整任务管理 UI。供应商边界和配套 Gateway 版本要求见 [Vidu 指南](vidu.zh.md#回执边界)；也不提供用户听到位置到模型历史的精确截断。
